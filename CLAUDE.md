## Команды

Виртуальное окружение уже создано, интерпретатор — `.venv/bin/python` (Python 3.12).
Активация через `source` в составной команде не переживает переход к следующему вызову —
надёжнее вызывать интерпретатор напрямую.

```bash
./.venv/bin/python -m pytest -q                  # весь набор, ~5 с
./.venv/bin/python -m pytest tests/test_api.py::test_trailer_format_region_is_last -q
./.venv/bin/python -m ruff check app tools tests
./.venv/bin/python -m uvicorn app.main:app --port 8000
```

Установка с нуля: `uv pip install -e ".[dev]"`, затем `python -m tools.fetch_yolo` за весами детектора.

Инструменты (все запускаются как модули: `python -m tools.<имя>`):

| Команда | Зачем |
|---|---|
| `tools.eval_uz --fetch 80 --run` | скачать выборку с platesmania и замерить точность |
| `tools.eval_uz --run --save-fails` | перезамер по уже скачанному, кропы ошибок в `data/eval/fails/` |
| `tools.eval_uz --compare models/*.pt` | сравнить детекторы на одной выборке |
| `tools.probe_model crops/*.jpg --chars` | диагностика распознавателя: обе головы, уверенность по символам |
| `tools.probe_model crops/*.jpg --all-variants` | перебрать варианты препроцесса |
| `tools.bench` | задержки и FPS |
| `tools.ws_client --video clip.mp4 --fps 8` | CLI-клиент WebSocket |
| `tools.build_dataset --fetch 300 --build` | собрать датасет для дообучения |

## Архитектура

Две модели последовательно, поверх — правила формата УЗ и голосование по кадрам.

```
кадр → YOLO (детекция пластин) → кроп с отступом
     → TPS-ResNet-BiLSTM-CTC (greedy + beam-альтернативы)
     → plate_rules: выбрать кандидата, подходящего под формат УЗ
     → tracker: склеить кадры в трек, голосовать
     → событие
```

### Порядок шагов различается для фото и видео

Это главное, что нужно понять про пайплайн.

**Фото (REST).** `ANPRPipeline.process_frame()` делает всё сразу: детекция →
распознавание всего найденного. Один кадр, один шанс, экономить нечего.

**Видео (`TrackedSession`).** Между детекцией и распознаванием вклинивается решение:

```
detect_plates() → tracker.update() по IoU → кого читать? → recognize_crops()
```

Причина в замере: на видео 90% вызовов распознавателя — это повторное чтение уже
решённого номера. Машина едет через кадр две секунды, а тяжёлая модель отрабатывает
по ней две сотни раз. `TrackedSession._needs_read()` читает трек, пока тот не набрал
`min_votes`, а дальше только если пластина выросла в `recheck_growth` раз или прошло
`recheck_frames` кадров.

Следствия, о которых легко забыть:

- **Склейка треков по тексту переехала.** В старом порядке она была вторым проходом
  внутри `tracker.update(texts=...)`. Теперь текста на момент трекинга нет, поэтому
  склейка делается после чтения — `PlateTracker.absorb_by_text()`.
- **`PlateResult.recognized`** различает свежее чтение и показ уже известного номера.
  У пропущенных пластин текст берётся из трека (`TrackedSession._from_track`).
- **Вернуть старое поведение** — `ANPR_SKIP_CONFIRMED=false`. Полезно при сравнении.

### Разделение состояния — ключевое

- **`ANPRPipeline`** ([app/core/pipeline.py](app/core/pipeline.py)) — без состояния. Инференс
  сериализован локом; параллелизм даёт батч и потоки torch.
- **`TrackedSession`** (там же) — состояние на источник: трекер, голосование, кулдауны событий.

Три точки входа переиспользуют один `ANPRPipeline`, но каждая держит свою `TrackedSession`:
REST (`/v1/recognize`, один кадр, без трекинга), WebSocket (`/ws/recognize`, кадры от клиента),
`StreamWorker` ([app/core/streams.py](app/core/streams.py), сервер сам читает RTSP/файл/камеру
в отдельном потоке).

### Чекпоинт распознавателя

Архитектура и алфавит **восстановлены по весам**, а не прочитаны из файла — см. докстринг
[app/core/model.py](app/core/model.py). Две CTC-головы, 95 классов (`string.printable[:94]`
плюс blank). Живые классы `head_anpr`: цифры и A-Z **кроме `I`**; `head_ctype`: цифры, `H`, `M`.

`load_model()` падает при несовпадении чекпоинта с моделью — это намеренно, лучше отказ на
старте, чем мусор в выводе.

### Выбор варианта по формату

Распознаватель возвращает greedy-результат и beam-альтернативы. `plate_rules.pick_best()`
чинит каждого кандидата (замены `0/O`, `1/I`, дедупликация CTC-повторов) и выбирает того,
кто уложился в формат УЗ. Если ни один не уложился — доверяем greedy, он честнее по
вероятности. Логика в [app/core/pipeline.py](app/core/pipeline.py), правила — в
[app/core/plate_rules.py](app/core/plate_rules.py).

### Трекинг и события

`PlateTracker.update()` идёт тремя проходами: IoU → совпадение текста → новые треки. Второй
проход нужен на подвижной камере, где один номер разваливался на девять треков.

Кулдаунов **два**: на трек (`tr.emitted_ts`) и на сессию (`TrackedSession._emitted` по тексту).
Второй ловит случай порванного трека, который иначе выдал бы одну машину несколько раз.

## Решения, которые выглядят как недоделки, но обоснованы замером

Прежде чем «чинить» что-то из этого списка, прочитайте комментарий рядом с настройкой в
[app/config.py](app/config.py) и [.env.example](.env.example).

- **`two_line=False`** — текущий чекпоинт не читает двухстрочные квадратные номера (0/4 на
  выборке), а на видео 36% кропов уходят на двойное чтение: 184 мс против 97. Включать после
  дообучения, а не «на всякий случай».
- **`det_retry_in_stream=False`** — второй проход детектора в 1536 стоит ~366 мс. Для
  одиночного фото оправдан (детекция 37/40 → 40/40), для видео нет: кадр без пластины там
  норма, следующий шанс придёт через 150 мс.
- **`head_ctype` не используется на белых номерах** — измерено 0/40 совпадений. Её вывод идёт
  в кандидаты только для жёлтых и зелёных (`ANPR_TYPE_HEAD_COLORS`), где алфавит совпадает.
  Гипотеза **проверена на 39 цветных и не подтвердилась**: +1 из 39, на жёлтых ровно 0.
  Настройка оставлена включённой — вреда нет, но улучшением это считать нельзя.
- **Регион у прицепов в третьей группе.** Формат `DDDD LL DD` — регион в конце, не в начале
  (`4169 AA 70`). У `PlateFormat` для этого есть поле `region_group`.
- **Определение цвета фона — эвристика по HSV и заметно врёт**: белые номера в тени уезжают
  в `black`. Для жёлтых и зелёных работает. Не стройте на цвете логику, которая должна быть
  надёжной.
- **`[tool.setuptools.packages.find]` с явным `include`** — без него автопоиск пакетов падает
  на `data/` и `models/` в корне.

## Замеры вместо ощущений

Все цифры в README получены `tools/eval_uz.py` на выборке номеров УЗ с platesmania (эталон
берётся из `alt`-атрибута фотографии — бесплатная разметка).

Для видео есть отдельная регрессия на размеченном вручную ролике — девять номеров,
эталон в [tests/video_ground_truth.json](tests/video_ground_truth.json). Само видео в
git не лежит, тест пропускается без переменной:

```bash
ANPR_TEST_VIDEO=~/Downloads/video_2026-08-07_11-26-52.mp4 \
  ./.venv/bin/python -m pytest tests/test_video.py -v -s
```

Он сравнивает быструю и полную схемы на одних кадрах и требует, чтобы быстрая нашла
всё то же. FPS не проверяется намеренно: на ноутбуке под нагрузкой цифры уезжают
вдвое, и жёсткий порог давал бы ложные падения.

Правки детектора, распознавателя, препроцесса или правил формата проверяются прогоном
`python -m tools.eval_uz --run` и сравнением с прежним результатом. Разница в одну-две позиции
на выборке из 80 — шум, а не улучшение. Не заявляйте улучшение без числа.

Отрицательный результат — тоже результат. Проверено и отброшено, повторять не нужно:
мультикроп (72→72), вертикальная обрезка (+1), перебор `crop_padding` (0.06 уже оптимален),
режим двух строк (184 мс против 97 при нуле верных чтений) и подмешивание `head_ctype`
для цветных (+1 из 39, на жёлтых 0).
